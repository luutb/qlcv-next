# Review report

Purpose: Communicate actionable defects and their disposition.
Status: Draft
Owner: Code Reviewer
Task / requirement reference: Record the actual task ID/link when using this template.

Use only for meaningful handoffs; combine artifacts when clearer. Status vocabulary: Draft, In Review, Approved, In Progress, Verified, Blocked, Superseded. Record authority for Approved and check evidence for Verified.

## Review scope

Base/head or snapshots, relevant requirements, independence/self-review, files/paths inspected and checks executed.

## Findings

ID | severity | file:line | trigger/evidence | impact | remediation | owner | disposition/retest evidence.

## Recommendation and limitations

No findings is not proof of correctness. Separate confirmed defects from untested risks; material risk acceptance needs authorized decision reference.

## Decisions and assumptions

Record sourced facts separately from assumptions; decision, owner/date, authority/evidence and consequences.

## Completion criteria

Relevant [gates](../gates.md), task AC and evidence required before completion; record actual disposition when used.

## Unresolved questions

Question/blocker | owner | required evidence/decision | effect on dependent work. Explicitly state none only when assessed.
